## Почему GHCR

Исходники и сборка уже находятся в GitHub. GitHub Actions публикует контейнер через
свой `GITHUB_TOKEN`, без отдельного аккаунта/секрета Docker Hub. Публичный контейнер
GHCR можно скачивать анонимно. Видимость пакета задаётся отдельно от публичности
репозитория; при первой публикации нужно выбрать Public в Package settings.

Docker Hub можно добавить позднее как зеркало. Он удобен привычным коротким именем
образа, но имеет лимиты скачиваний для бесплатных/анонимных клиентов. См.
[GHCR](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-container-registry)
и [лимиты Docker Hub](https://docs.docker.com/docker-hub/usage/).

## Запуск

Из корня этого репозитория:

```sh
umask 077
printf 'JWT_SECRET=%s\n' "$(openssl rand -hex 32)" > .env
docker compose pull
docker compose up -d
docker compose ps
```

Команда создания `.env` предназначена для первого запуска. При обновлении сохраните
существующий JWT_SECRET: интеграция должна подписывать конфигурацию тем же секретом.
`.env` не коммитится. Доступ по умолчанию: <http://127.0.0.1:8080>.
Compose сохраняет данные, cache, логи и пользовательские шрифты в именованных volumes.

Для прямого доступа с других машин задайте `OFFICIER_BIND=0.0.0.0`; для реального
использования разместите сервер за HTTPS reverse proxy и передайте ему корректный
внешний адрес. Веб-приложение пользователя и DocumentServer должны иметь сетевой
доступ друг к другу по адресам документов и callback.

Публичность registry означает возможность скачать образ, а не публичный доступ к
вашим документам. JWT включён. Для интеграции:

```text
https://YOUR_OFFICIER_HOST/web-apps/apps/api/documents/api.js
```

React-пакет без iframe развивается отдельно. Этот контейнер предоставляет обычные
веб-редакторы ONLYOFFICE с iframe-интеграцией и серверные API.

## Состав сборки

- База: ONLYOFFICE DocumentServer 9.4.0, digest закреплён в Dockerfile.
- SDK, web-apps, шрифты и нативный `x2t` взяты из этой базы.
- `Common`, `DocService`, `FileConverter` и `Metrics` поставляются из закреплённых
  открытых исходников с патчами Officier. npm-зависимости устанавливаются через
  `npm ci` с upstream shrinkwrap-файлами.
- Серверные launcher-файлы запускают наши JS-исходники через закреплённый Node.js 22;
  это гарантирует использование патчей вместо встроенного кода upstream executable.
- Wire/build version сервера синхронизируется с версией пакета в базовом образе.
- `/welcome/officier.html` содержит сведения о модификации, исходном разработчике,
  лицензии и доступе к исходникам.
- Корпоративное оформление (`docker/branding`, изменения от 2026-10-13): в редакторах скрыты
  логотип, справка, отзывы, подсказки и ссылки ONLYOFFICE, заголовки вкладок русские.
  Значения по умолчанию добавляются в `api.js` и не переопределяются интеграцией.
  Правовая информация (ONLYOFFICE / Ascensio System SIA, факт и даты изменений, лицензия,
  ссылка на `/welcome/officier.html`) показывается в «Файл → О программе» каждого редактора.
  Параметр `customization.officier.openComments: true` открывает панель комментариев после
  загрузки документа (добавлен в `documenteditor` при сборке).
- Плагин-панель «Рецензирование» (`docker/plugins/qms-review`, вариант `qms-review-left` для левой
  стороны) устанавливается в `sdkjs-plugins`; включает её шлюз СМК через `editorConfig.plugins`.
  Файлы плагинов кэшируются браузерами на год, поэтому обёртка `api.js` загружает плагины этого
  сервера по пути с меткой кэша (`/9.4.0-<метка>/sdkjs-plugins/...`), которая меняется при каждом
  запуске. Обновить файлы без перезапуска: скопировать их в контейнер, пересоздать рядом сжатые
  копии `*.gz` (nginx отдаёт их вместо файлов, `gzip_static on`) и выполнить
  `documentserver-flush-cache.sh` (меняет метку, перечитывает nginx, сессии не прерываются).
  Тексты задаются в `docker/branding/branding.json`; `sourceUrl` должен вести на исходники
  именно разворачиваемой изменённой версии (AGPLv3, раздел 13).
- Сервис `qms-gateway` (`gateway/`) — API модуля СМК для бэкенда портала, см.
  [интеграцию с СМК](qms-integration.md).
- `/welcome/officier-build.json` содержит точный commit и состав сборки.

Это сборка собственного серверного runtime на upstream образе, а не полная
перекомпиляция C++-движка, шрифтов и всех frontend-ресурсов. Их исходники и ревизии
доступны через подмодули репозитория и тег `v9.4.0` upstream.

Community использует standalone профиль с памятью процесса для ряда серверных
структур и встроенным обработчиком конвертации. Снятые продуктовые квоты не добавляют
кластеризацию, отказоустойчивость или неограниченную производительность. Для первой
версии предполагается один экземпляр сервера; активное состояние совместного
редактирования не следует считать устойчивым к перезапуску процесса.

## Производительность и ёмкость

Изменения от 2026-10-13/14 (`compose.yaml`, `docker/install.sh`, `docker/config`, патч 0006):

- Совместное редактирование в режиме `fast` (задаёт шлюз СМК): ввод соавтора отправляется сразу,
  без кнопки «Сохранить» и без ожидания.
- nginx запускает по одному worker на ядро, `worker_connections` равен лимиту открытых файлов
  (`nofile` 65535). Каждый открытый редактор держит одно WebSocket-соединение.
- Неактивные сеансы не отключаются (`expire.sessionidle` = `"0"`). Пустая строка там недопустима:
  сервер не может её разобрать, и периодическая проверка сеансов перестаёт работать. Это
  проверяет `tests/config.test.cjs` при сборке.
- Конвертация (открытие, сохранение, PDF) идёт параллельно: число обработчиков равно числу ядер ×
  `FileConverter.converter.maxprocesscount`. В upstream Community встроенный конвертер обрабатывал
  задачи по одной.
- Лимиты: несохранённые изменения одного документа до 80 МБ (`editor.maxChangesSize`), распакованный
  DOCX/PPTX/VSDX до 250 МБ, XLSX до 500 МБ.
- `stop_grace_period: 2m`: при остановке контейнер сохраняет открытые документы
  (`documentserver-prepare4shutdown.sh`), а не обрывает их через 10 секунд.
- Списки шрифтов, превью тем и JS-кэш конвертера создаются при сборке образа
  (`GENERATE_FONTS=false`). Upstream пересоздаёт их через несколько минут после старта и затем
  перезапускает DocService. Контейнер в это время уже `healthy` и принимает пользователей, а
  перезапуск обрывает их сеансы вместе с несохранёнными правками. Плагины из маркетплейса при
  старте не скачиваются (`PLUGINS_ENABLED=false`): в редакторах работают только встроенные в образ.

Свои шрифты кладутся в volume `fonts` (`/usr/share/fonts/truetype/custom`) или в
`Data/custom-fonts`. После этого контейнер перезапускают: при остановке открытые документы
сохраняются, а при старте точка входа (`officier-fonts ensure`) пересоздаёт списки ещё до запуска
DocService. Пересоздание идёт, только если набор шрифтов изменился.

```sh
docker compose restart officier
```

Ёмкость. Память DocService (`--max-old-space-size`) по умолчанию равна 60% памяти контейнера,
её можно задать вручную через `OFFICIER_DOCSERVICE_HEAP_MB`. Защита памяти Community
ограничивает число **разных документов**, одновременно открытых на редактирование:

```text
документов ≈ (heap − 256 МБ) / max(maxChangesSize / 4, 20 МБ) = (heap − 256 МБ) / 20 МБ
```

| Память сервера | heap DocService | Документов на редактирование |
| --- | --- | --- |
| 4 ГБ | ~2,4 ГБ | ~110 |
| 8 ГБ | ~4,8 ГБ | ~235 |
| 16 ГБ | ~9,6 ГБ | ~480 |
| 32 ГБ | ~19 ГБ | ~970 |

Пользователи к уже открытому документу и просмотр в лимит не входят: один регламент могут
одновременно редактировать все участники маршрута. Новые документы сверх лимита открываются
только на просмотр (в журнале: `forced view mode by community memory guard`).

Масштабирование только вертикальное: сеансы хранятся в памяти одного процесса, поэтому
несколько экземпляров за балансировщиком не работают. Нужно больше документов — добавьте
памяти; нужно быстрее открывать и сохранять — добавьте ядер.

Замер на стенде разработки (WSL, 4 ядра, 3,7 ГБ, процессор делится с Windows),
`docker/smoke/perf.mjs`, 2026-10-14:

| Что | Время |
| --- | --- |
| Ввод соавтора виден другому участнику | 0,2–0,35 с (медиана) |
| Правка согласующего появляется в панели «Рецензирование» разработчика | 0,13 с (до настройки 1,5 с) |
| Короткий документ, пока конвертируются два больших | 2 с, как на свободном сервере |
| Большой документ (~60 страниц) в PDF | 5 с; 8 одновременно — 26 с вместо 40 с подряд |

Конвертация упирается в процессор: одна конвертация занимает 2–3 ядра. На сервере с большим
числом ядер одновременных конвертаций без замедления будет больше. Синхронный `/converter`
проверяет готовность раз в секунду, поэтому его время кратно секунде.

## Поставка

`bash scripts/package-release.sh 0.2.0` собирает в `release/0.2.0/` всё для установки на сервер без
доступа к сборочной машине: оба образа (`docker save`), архив исходников, `deploy/compose.yaml`,
пример HTTPS-прокси, документацию и `SHA256SUMS`. Архив исходников встраивается в образ и
раздаётся по `/welcome/officier-source.tar.gz`, а его SHA-1 становится ревизией образа. Порядок
установки и интеграции с порталом — [передача разработчику](handover.md).

## Самостоятельная сборка

```sh
git submodule update --init --depth 1 -- server
python3 scripts/patches.py apply
docker build --platform linux/amd64 \
  --build-arg SOURCE_REVISION="$(git rev-parse HEAD)" \
  --build-arg OFFICIER_VERSION=0.1.0 \
  -t officier:0.1.0 .
```

Сборка проверяет применённые патчи, запускает unit-тесты runtime-флагов и отказывается
собираться с отсутствующим patch overlay или неожиданной версией базового пакета.

## Публикация

Запустите **Build and publish Officier container** в Actions с новым номером версии.
Workflow сначала собирает образ, затем запускает его и браузерный smoke-тест, и только
после успешных проверок публикует version-тег, `sha-COMMIT` и `latest`.
Уже опубликованный version-тег не перезаписывается. Для воспроизводимого развёртывания
используйте конкретную версию или digest вместо `latest`.

Проверки перед публикацией:

1. `/healthcheck`, версия сервера и включённые флаги через подписанный Command API.
2. Отклонение запроса с неверным JWT.
3. Открытие настоящего DOCX в Chromium, изменение текста и callback сохранения.
4. Проверка сохранённого `word/document.xml` и повторное открытие файла в режиме view.

Тестовая фикстура в CI разрешает серверу скачивать документ с private IP runner-а.
Это настройка только smoke-контейнера; производственный Compose её не включает.
Smoke-тест не является нагрузочным тестом или полным регрессионным тестом всех форматов.

После первой публикации выставьте Public в настройках контейнерного пакета и
проверьте скачивание без Docker credentials. Эта настройка не применяется автоматически
из-за публичного статуса репозитория.
